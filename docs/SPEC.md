# 仕様とロードマップ

## コンセプト

**プログラムの計算が導く、今日の献立。** 献立はアルゴリズム（数理最適化）が決め、AI はその上でリアクション・解説・相談・モチベーション維持を担当する。

## 方針

- 判断の中心は決定的なプログラム（最適化・栄養計算）。AI は計算結果やアプリの状態を**構造化データ**で受け取り、必要ならプログラムを**ツール**として呼ぶ
- AI がなくても全機能が使える
- 試行錯誤しやすいよう、データ（食材・料理）・計算（planner）・画面（features / pages）を分ける
- 画面が増えたら整理する。スマホの下部ナビは 6 項目まで

## 献立の計算（Phase 1）

`src/lib/planner/model.ts` が CPLEX LP 形式の混合整数計画モデルを作り、HiGHS（WebAssembly）が Web Worker の中で解く。
プリセット（バランス・節約・栄養重視・時短）ごとに Worker を分けて並列に計算する（`src/lib/planner/client.ts`）。

| 要素       | モデルでの扱い                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 毎日の構成 | 主菜・副菜・汁物を 1 品ずつ（等式制約）。丼・カレー・麺は主食を兼ね、ご飯の栄養を足さない             |
| 買い物     | 食材ごとに買うパック数（整数変数）。使う量 ≤ パック × 個数 + 在庫。費用と余り（傷むもの）を目的関数に |
| 日持ち     | 買い物の日から日持ちを超える日の候補から外す（冷凍を使う設定なら肉・魚は 14 日）                      |
| 栄養       | 1 日ごと・1 人分の目標（食事摂取基準 × 夕食の割合）からの不足・超過を割合で罰する（ソフト制約）       |
| くり返し   | 期間中は同じ料理を出さない。過去の献立に近いほど罰する。同じたんぱく源の主菜が 2 日続くと罰する       |
| 重なり     | 同じ日の料理どうしで主役の食材が重ならない（肉じゃが＋ポテトサラダなど）                              |
| 旬・気候   | 旬の食材の割合を加点、季節外れを減点。最高気温（予報または平年値）に合う温かい・冷たい料理を加点      |
| 好み       | 好き・苦手を加点・減点、「使わない」は候補から除外                                                    |
| 調理時間   | 主菜 + 副菜・汁物 × 0.6 が目安（平日・休日）を超えた分を罰する                                        |

係数は `src/lib/planner/scoring.ts` の `COEF`（円に換算した重み）にまとめている。

## 分析（Phase 2）

- 行データ: `src/lib/analysis/dataset.ts` の `DayRow`（1 日分の夕食。栄養・スコア・食材費・旬・たんぱく源）
- 気づき: `src/lib/analysis/insights.ts` の `INSIGHT_RULES` に関数を足す。データから決定的に計算する
- 分析ツール: `src/features/analysis/registry.ts` の `ANALYSIS_TOOLS` にコンポーネントを足す。どのツールも `DayRow[]` を受け取り、クリックで掘り下げる（日付を押すとその日の献立を開く）
- グラフ: ECharts（必要な部品だけ読み込む）。色は検証済みのカテゴリ色（`--viz-1`〜`--viz-8`）を固定の順番で使い、ダークモードは別の段階の色を使う

## AI（Phase 3）

- 入口: `src/features/ai/aiClient.ts`。いつもの AI と「応答ごとの AI」（chat / reaction / generate）を振り分ける。端末内の AI は `registerLocalBackend` で登録する
- クラウド AI: `src/lib/cloud/`（LLLM-Study と同じ実装）。API キーはアプリの合言葉（PBKDF2 + AES-GCM）で暗号化して localStorage に保存
- アプリの状態: `src/features/ai/appContext.ts` が構造化データ（今日の献立・これからの献立・気づき・買い物・旬・好み）を作り、システムプロンプトに入れる
- ツール: `src/features/ai/tools.ts`（get_menu / get_day_nutrition / search_dishes / suggest_swaps / propose_swap / get_shopping_list / get_insights）。献立を変えるのは提案まで（ユーザーが押して確定）
- キャラクター: `src/features/ai/personas.ts`。2 人のときは順番に答え、2 人目は 1 人目の発言を「[名前] 」付きで受け取る
